# Очистка журналов отклонений входящих запросов

[English](README.md) | Русский

Эта служебная команда удаляет исторические записи об отклонениях входящих запросов из `ops_error_logs`, не затрагивая несвязанные ошибки аутентификации, базы данных, квот, биллинга или upstream-сервисов.

Команды ниже предполагают, что текущий каталог — `backend/`.

## Предварительный просмотр и выполнение

Всегда требуется явная граница времени в формате RFC 3339. Без параметра `--execute` команда работает в режиме предварительного просмотра.
Команда загружает тот же bootstrap config/environment, что и приложение. `--batch-size` принимает `1-5000`, default — `5000`.

```sh
# Показать подходящие строки без удаления
go run ./cmd/cleanup-ingress-reject-logs --before 2026-07-17T00:00:00Z

# Удалить подходящие строки
go run ./cmd/cleanup-ingress-reject-logs --before 2026-07-17T00:00:00Z --execute
```

Запускайте вариант с `--execute` только после обновления всех экземпляров приложения. Иначе старый экземпляр может снова создавать записи об отклонениях ниже выбранной временной границы.

Классификатор намеренно сохраняет инвариантные ошибки, например `USER_NOT_FOUND`, ошибки базы данных, квот/биллинга и upstream-сервисов.

## Завершение очистки схемы

После проверки rollout и очистки журналов:

1. Создайте и проверьте актуальную резервную копию базы данных.
2. Назначьте окно обслуживания.
3. Запустите финализатор с включённым `ON_ERROR_STOP`:

```sh
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 \
  -f scripts/finalize-ingress-reject-cleanup.sql
```

Финализатор удаляет устаревшую таблицу аудита с ключами в открытом виде и связанные attribution-колонки. Перед запуском проверьте SQL: этот этап разрушительный и не относится к безопасному dry-run выше.
После транзакции отдельно выполните `VACUUM (ANALYZE) ops_error_logs;` в обычное maintenance window; в finalizer эта команда намеренно оставлена закомментированной.
