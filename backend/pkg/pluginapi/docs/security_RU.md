# Граница безопасности плагинов

[中文](security.md) | Русский

## Какую изоляцию это даёт

- Приватная реализация поставляется отдельным бинарным файлом; публичный исходный код host-а не содержит её бизнес-логики.
- Процессный протокол избегает Go dynamic linking и shared-memory ABI.
- Package signature и file hash защищают от несанкционированной подмены.
- UI использует краткоживущий URL, отдельный Bridge Token и sandbox iframe.
- При отказе плагина OAuth plugin path завершается fail-closed и не переключается молча на другое сетевое поведение.

## Чего это не гарантирует

- Закрытый бинарный файл всё равно может быть проанализирован через reverse engineering.
- Дочерний процесс не является OS sandbox.
- Плагин имеет права на файлы, environment variables и сеть, доступные сервисному пользователю Sub2API.
- Подпись пакета подтверждает издателя, но не доказывает отсутствие уязвимостей или соответствие правилам provider-а.

## Требования к развёртыванию

- Официальный OpenAI Transport использует встроенный public key host-а; добавляйте в `plugins.trusted_publishers` только проверенные third-party public keys.
- Запускайте Sub2API от отдельного низкопривилегированного системного пользователя.
- Ограничивайте для этого пользователя файловые права, исходящую сеть и environment variables.
- Не передавайте в среду плагина лишние secrets.
- Для обновлений плагинов сохраняйте старый пакет и рабочий rollback-процесс.
- Записывайте операции установки, включения, отключения, настройки и удаления, но не записывайте plaintext конфигурации.

## Чувствительные данные

Плагин обрабатывает реальные OAuth Authorization headers. Он должен избегать записи request headers, request body, proxy credentials и чувствительных upstream responses в logs или diagnostic messages. В UI-конфигурации не должны появляться OAuth Tokens.
