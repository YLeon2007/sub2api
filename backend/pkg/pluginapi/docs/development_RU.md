# Руководство по разработке плагинов

[中文](development.md) | Русский

## Стабильная граница

Текущий host поддерживает только capability `openai.oauth.outbound_transport.v1`. Плагин отвечает за установление реального upstream HTTP/TLS-соединения; Sub2API отвечает за выбор аккаунта, жизненный цикл OAuth Token, downstream-протокол, разбор ответа, SSE, сопоставление ошибок, учёт usage и billing.

Плагин не должен изменять путь API Key и не должен самостоятельно обновлять или сохранять OAuth Token.

## Рекомендуемая структура

```text
plugin/
├── cmd/<plugin>/main.go
├── internal/config/
├── internal/transport/
├── ui/index.html
├── ui/assets/
├── tools/packager/
├── manifest.source.json
└── README.md
```

Входная точка должна только вызывать `pluginv1.Serve`. Разбор конфигурации и transport-реализацию держите в отдельных пакетах, чтобы их можно было unit-тестировать без запуска дочернего процесса.

## Runtime-методы

| Метод | Требования |
|---|---|
| `GetInfo` | ID, версия, протокол и capability должны совпадать с манифестом |
| `Health` | Возвращает, может ли процесс принимать новые запросы; не выполняет дорогие проверки |
| `ValidateConfig` | Строго разбирает конфигурацию и возвращает полностью нормализованный JSON |
| `ApplyConfig` | Атомарно применяет конфигурацию; при ошибке сохраняет старую конфигурацию |
| `TestConfig` | Проверяет текущую среду и сохранённую конфигурацию, возвращает краткую диагностику |
| `Forward` | Двунаправленно передаёт запрос и исходный HTTP-ответ |

Порядок кадров запроса: `start`, ноль или больше `body_chunk`, затем `body_end`. Порядок кадров ответа: `start`, ноль или больше `body_chunk`, затем `end`. Ошибки, после которых нельзя продолжать обработку, передаются кадром `error`.

`request_sent` обязан честно показывать, мог ли запрос уже дойти до upstream. Если значение `true`, host запрещает автоматическое переключение аккаунта с повтором. Возвращайте `false` только когда точно известно, что upstream Transport ещё не вызывался.

## Конфигурация

- JSON-поля всегда используют `snake_case`.
- Отклоняйте неизвестные поля, недопустимые диапазоны и защищённые HTTP-заголовки.
- Конфигурация по умолчанию должна быть полной; пустой объект должен нормализоваться во все поля по умолчанию.
- При сохранении плагин сначала валидирует и применяет конфигурацию, затем host шифрует её и записывает в базу данных.
- Если запись в базу данных не удалась, host попытается восстановить старую конфигурацию; плагин должен допускать повторное применение.

## Управление ресурсами

- Повторно используйте HTTP Transport и пул соединений; не создавайте новый пул для каждого запроса.
- После смены конфигурации закрывайте старые idle-соединения.
- Используйте stream context для отмены DNS, соединения, загрузки тела запроса и чтения ответа.
- Всегда закрывайте тело upstream-ответа.
- Не держите внутри плагина бесконечный cache клиентов, разделённый по аккаунтам.

## Минимальный набор тестов

- Значения конфигурации по умолчанию, неизвестные поля, граничные значения и deep copy.
- Идентичность плагина и версия протокола.
- Chunked request body, отсутствие тела запроса и фиксированный `Content-Length`.
- Статус ответа, повторяющиеся заголовки, streaming response и ошибки чтения ответа.
- Отмена context, выход процесса плагина и timeout.
- Включённый и отключённый proxy.
- Package hash, подпись, path traversal и runtime для целевой платформы.
- Загрузка UI Bridge, сохранение, тестирование, ошибки и timeout.

Перед публикацией также запускайте интеграционные тесты процесса плагина в host-е на реально собранном пакете.
