# Защита периметра и входящих HTTP-запросов

[English](EDGE_SECURITY.md) | Русский

Sub2API поддерживает длительные запросы SSE и WebSocket. Защищайте приём запросов и отдельные операции с сокетами, не устанавливая фиксированного тайм-аута на весь ответ. Исправно работающая генерация может оставаться открытой, пока вышестоящий сервис обрабатывает запрос.

## Настройки приложения по умолчанию

- `server.max_header_bytes: 65536` ограничивает заголовки HTTP/1-запроса 64 KiB; Go сопоставляет это значение с соответствующим лимитом списка заголовков HTTP/2.
- `server.read_header_timeout: 10` ограничивает время медленной передачи заголовков. Он не ограничивает обработку запроса или потоковую передачу ответа.
- `server.max_request_body_size: 268435456` — абсолютный защитный предел 256 MiB.
- `gateway.max_body_size: 268435456` остаётся доступен для мультимодальных интерфейсов, Gemini, изображений, видео и пакетной обработки изображений.
- `gateway.text_max_body_size: 33554432` ограничивает заведомо чисто текстовые точки `/embeddings` и `/alpha/search` размером 32 MiB.
- `gateway.request_body_memory_budget_bytes: 1073741824` задаёт общий бюджет буферизации 1 GiB для маршрутов шлюза и их алиасов. Выделения для фрагментов, сплошной копии тела, распакованных данных, нормализации JSON и резерва декодера Zstd учитываются до выделения памяти. Каждая стадия освобождает учёт промежуточных выделений, на которые больше не ссылается: фрагментов после сборки, сжатого входа и рабочего пространства декодера после декодирования, принадлежащего стадии входа после нормализации. Учёт памяти итогового тела сохраняется до возврата из обработчика, в том числе на протяжении длительного SSE-ответа. Буфер предварительного чтения, на который ещё может ссылаться middleware, учитывается вместе с нормализованной копией. Исчерпание возвращает 503 с `Retry-After`; превышение размера отдельным запросом остаётся ошибкой 413. Устанавливайте бюджет по памяти экземпляра, оставляя запас для соединений, состояния преобразования, кэшей и GC. Это консервативный учёт памяти при приёме запросов, а не жёсткая граница размера всей кучи или RSS.
- Распакованный вывод сжатого запроса ограничен 64 MiB; превышение отклоняется, а не обрезается. Для Zstd дополнительно установлены предел окна 8 MiB и один рабочий поток декодера на запрос.
- `gateway.request_body_read_timeout_seconds: 120` ограничивает зависшее чтение тела; `gateway.downstream_write_timeout_seconds: 120` ограничивает каждую запись или flush. После успешной операции её deadline снимается, поэтому ожидание вышестоящего сервиса не расходует общий бюджет времени ответа. Нуль отключает соответствующее ограничение.
- `gateway.max_line_size: 524288000` сохраняет прежний предел строки SSE в 500 MiB, необходимый для больших изображений 4K в base64, вывода генерации изображений и ответов с несколькими изображениями. Обновление не снижает этот предел совместимости незаметно. `sse_event_max_bytes: 0` наследует его для каждого полного события; `sse_event_max_lines: 4096` дополнительно ограничивает поток коротких строк без пустого разделителя. `sse_queue_max_bytes: 8388608` ограничивает число байтов полезных данных в очереди; строка размером более 8 MiB может занимать очередь одна, вплоть до предела строки или события. Текущая строка у потребителя и буфер сканера/чтения у производителя занимают дополнительную, но ограниченную память. Бюджет очереди 8 MiB не уменьшает максимально допустимый размер одного кадра изображения. Снижайте лимиты строк и событий, только если это допускают поддерживаемые модели и размеры вывода. Явные ограничения байтов и строк события также применяются к предварительным фильтрам Grok billing-ping и client-tool.
- Отсоединённые попытки обращения к вышестоящему HTTP-сервису могут после отключения клиента продолжать собирать поздние данные об использовании для тарификации, но лишь в течение конечного окна дочитывания. Его длительность соответствует тайм-ауту интервала данных потока (по умолчанию 180 секунд). Перенаправление запросов OpenAI image по API-key/OAuth использует тайм-аут изображений (по умолчанию 900 секунд); для Grok media сохраняется общий тайм-аут дочитывания. Поступающие ping-сообщения не перезапускают окно. Это заменяет прежнее неограниченное дочитывание после отключения: по истечении окна попытка отменяется, и для расчёта доступны только данные использования, полученные до отмены. Финальные данные, пришедшие позже, могут быть потеряны, даже если провайдер продолжает генерацию и начисление платы. Отключение тайм-аута простоя потока не отключает этот защитный предел дочитывания (180 секунд; для OpenAI image API-key/OAuth сохраняется запасной предел 900 секунд).
- Значения H2C по умолчанию: 50 одновременных потоков на соединение, окно загрузки соединения 2 MiB и окно загрузки потока 512 KiB.
- Злоупотребления недействительными учётными данными ограничиваются в процессе по доверенному IP клиента (подсеть IPv6 `/64`): 120 неудач за 60 секунд, затем блокировка на 60 секунд. Это защитная мера отдельного экземпляра; контроль на нескольких экземплярах по-прежнему должен выполняться балансировщиком, CDN или WAF.

Не заменяйте эти меры одним семафором запросов на всё приложение: SSE-запрос может обоснованно занимать его многие минуты. Ограничивайте соединения и неаутентифицированные запросы на периметре; параллелизм аутентифицированного пользователя/API-ключа и байты буферизованных запросов остаются ответственностью приложения.

Каждый из кэшей сеансов совместимости — digest-сеансов, привязок продолжения Responses и привязок Anthropic digest — имеет фиксированные ограничения 16 384 записи и 32 MiB учитываемой памяти, включая 512 байтов служебных данных на запись. Эти пределы сейчас не настраиваются. При достижении любого из них вытесняется запись, использовавшаяся наиболее давно, даже если её TTL ещё не истёк; следовательно, TTL не гарантирует сохранность привязки продолжения. Пока кэш непуст, активная проверка истечения срока выполняется не чаще одного раза в минуту; остановка сервиса прекращает очистку. При настройке ёмкости следите за отказами 503 из-за бюджета тела, ошибками превышения размера ответа, скоростью выделения памяти, удерживаемой кучей после GC, числом goroutine, очередями задач учёта использования и ожиданием соединений с базой данных. Очереди уведомлений могут пропускать сообщения best effort при перегрузке или остановке и записывать число пропусков в журнал; сохранение уже начисленных списаний не отбрасывается по этой политике уведомлений. Когда flusher квот платформы отключён, обновление зеркала квот выполняется внутри задачи учёта использования с отдельным пятисекундным deadline для базы данных. Ошибки продолжают подсчитываться и записываться для сверки; у этого пути нет надёжной автоматической повторной попытки. Основное начисление идемпотентно фиксируется до обновления зеркала. При значении по умолчанию `gateway.usage_record.overflow_policy: sync` переполненная очередь задач использования приводит к выполнению задачи в отправившем её обработчике. Поэтому задержка базы данных может дополнительно задержать отправку данных использования и завершение обработчика на время отдельной пятисекундной попытки сохранения квоты, помимо остальной работы с использованием. Настроенное число рабочих потоков не является жёстким глобальным пределом параллельных операций с базой данных.

## Расчёт бюджета памяти тела запроса

Рассчитывайте `request_body_memory_budget_bytes` на итоговые выделения памяти для тел всех активных запросов и пиковое рабочее пространство запросов, которые сейчас читаются, декодируются или нормализуются. Длительность потоковой передачи увеличивает число удерживаемых тел даже после завершения их загрузки. Бюджет нельзя рассчитывать только по числу одновременных загрузок; снятие учёта выделения не заставляет Go немедленно освободить ставшую недостижимой память.

Например, 200 длительных потоков, удерживающих по 4 MiB, займут в учёте около 800 MiB до новых загрузок и декодирования. Ещё 32 одновременно работающих декодера Zstd могут зарезервировать 256 MiB только под окна, превысив бюджет по умолчанию в 1 GiB ещё до учёта их входных и выходных буферов. Увеличивайте бюджет для такой нагрузки только при достаточной памяти экземпляра либо сокращайте параллелизм и размеры запросов. Оставляйте отдельный запас памяти под кадры SSE (они могут быть больше бюджета очереди), состояние преобразования, кэши, соединения и GC. Значение бюджета `0` отключает допуск по памяти входящих запросов, а не ограничивает RSS.

Завершение вызова устаревшего инструмента Read по-прежнему проверяет растущий префикс аргумента JSON. Инкрементальное хранение устраняет повторные выделения памяти для префикса, но затраты CPU на проверку могут оставаться квадратичными для больших аргументов, поступающих множеством маленьких дельт. Измеряйте это отдельно от экономии выделений памяти: суммарные выделенные байты в бенчмарках — не удерживаемая куча и не RSS.

## Доверенные IP-адреса клиентов

`security.trust_forwarded_ip_for_api_key_acl` по умолчанию включён для совместимости при обновлении. Пока он включён, необработанные заголовки пересылки берут на себя определение IP клиента для журналов и чувствительных к безопасности путей. Пользовательские заголовки из `security.forwarded_client_ip_headers` проверяются в заданном порядке до встроенных запасных `CF-Connecting-IP`, `X-Real-IP` и `X-Forwarded-For`. Имена заголовков не зависят от регистра, нормализуются при загрузке, дедуплицируются и ограничены 16 уникальными допустимыми именами HTTP-полей. Значения заголовков должны содержать IP-адреса в буквальной форме; поддерживаются значения через запятую, недопустимые элементы пропускаются, публичным адресам отдаётся предпочтение перед частными запасными адресами.

Список можно задать в YAML либо в переменной среды `SECURITY_FORWARDED_CLIENT_IP_HEADERS` со значениями через запятую; явно пустое значение переменной среды очищает значения YAML. Список также можно изменять в административных настройках безопасности; обновление применяется во время работы без перезапуска. Для каждого запроса переключатель и список заголовков считываются единым снимком, поэтому запрос не смешивает старые и новые настройки. При выключенном переключателе пользовательские заголовки полностью игнорируются. В этом режиме определяющей является цепочка `server.trusted_proxies` в Gin: укажите только точные CIDR/IP адресов, непосредственно подключающихся к Sub2API. Явно пустой список означает, что пересланным IP клиентов доверия нет.

При первом обновлении до этого режима прежнее значение `false` меняется на `true` только в случае, когда `server.trusted_proxies` не был явно настроен; явные политики прокси остаются в безопасном режиме. На новых установках настроенный список пользовательских заголовков сохраняется при инициализации базы данных. На существующих установках отсутствующее значение в базе заполняется из YAML-конфигурации. Скрытый маркер миграции предотвращает перезапись последующих изменений администратора. Если настройки невозможно прочитать или сохранённый список пользовательских заголовков некорректен, процесс безопасно переключается на режим доверенных прокси без пользовательских заголовков. Если запись миграции не удалась, вычисленный режим остаётся действующим для текущего процесса, а при запуске записывается предупреждение.

Режим совместимости принимает пересылаемые заголовки без проверки непосредственного узла соединения, включая любой настроенный пользовательский заголовок. Пока он включён, защищайте origin от прямого доступа. При использовании CDN межсетевой экран должен пропускать к origin только CDN или балансировщик, а этот прокси должен перезаписывать каждый доверенный заголовок IP клиента, а не дописывать к нему недоверенное значение клиента.

Пример прокси на том же хосте:

```yaml
server:
  trusted_proxies:
    - 127.0.0.1/32
    - ::1/128
```

## Базовая конфигурация Nginx

Определите общие зоны в блоке `http`. Настройте частоты по измеренному легитимному трафику: значения ниже — консервативная отправная точка, а не универсальные целевые показатели ёмкости.

```nginx
limit_conn_zone $binary_remote_addr zone=sub2api_conn:20m;
limit_req_zone  $binary_remote_addr zone=sub2api_auth:20m rate=5r/s;
limit_req_zone  $binary_remote_addr zone=sub2api_api:40m rate=30r/s;
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 443 ssl http2;
    server_name api.example.com;

    client_header_timeout 10s;
    client_max_body_size 256m;
    large_client_header_buffers 4 16k;
    limit_conn sub2api_conn 40;

    location ~ ^/(auth|api/auth)/ {
        limit_req zone=sub2api_auth burst=10 nodelay;
        proxy_pass http://127.0.0.1:8080;
    }

    location ~ ^/(v1/)?(embeddings|alpha/search)$ {
        client_max_body_size 32m;
        limit_req zone=sub2api_api burst=60 nodelay;
        proxy_pass http://127.0.0.1:8080;
    }

    location / {
        limit_req zone=sub2api_api burst=60 nodelay;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_buffering off;
        proxy_request_buffering off;
        proxy_read_timeout 1800s;
        proxy_send_timeout 1800s;
        proxy_pass http://127.0.0.1:8080;
    }
}
```

Если gzip Nginx включён в блоке `http`, исключите `text/event-stream` из `gzip_types` и не используйте для Sub2API `gzip_types *`. Настройка `proxy_buffering off` выше отключает буферизацию прокси, но не отключает фильтр сжатия gzip для ответа. Для обычных ответов задайте явный список:

```nginx
gzip on;
gzip_types text/plain text/css application/json application/javascript application/xml image/svg+xml;
```

Если общая глобальная конфигурация не позволяет исключить SSE по типу содержимого, задайте `gzip off;` в location, обслуживающих потоковые API-маршруты. Сжатие веб-интерфейса и статических ресурсов при этом сохраняется.

Не используйте входное значение `$http_x_forwarded_for`, если обработка real-IP в Nginx не ограничена явно доверенными CIDR прокси.

## Caddy и CDN

Поставляемый `deploy/Caddyfile` устанавливает предел заголовков 64 KiB, тайм-аут заголовков 10 секунд, абсолютный предел тела 256 MiB и перезаписывает пересылаемые адреса по непосредственному TCP-узлу. Поэтому это базовая конфигурация для прямого подключения к Caddy. Не используйте её строки пересылки `{remote_host}` без изменений за CDN: все клиенты будут отнесены к исходящему адресу CDN, из-за чего агрегация отказов и ограничитель неудачной аутентификации объединят несвязанных пользователей.

Поставляемая конфигурация Caddy не задаёт `flush_interval`, позволяя Caddy автоматически отправлять ответы `text/event-stream` и одновременно передавать отмену клиента вышестоящему сервису. Не задавайте эту настройку глобально: положительные значения могут увеличить задержку потока, а особый режим `-1` в Caddy 2.6.2 также приводит к продолжению проксируемых запросов после отключения клиентов. Для сжатия конфигурация использует явный список типов содержимого ответа. Не заменяйте его на `text/*` или сокращение `encode gzip zstd`: оба варианта включают `text/event-stream` и могут буферизовать SSE до конца ответа. Оставляйте потоковые ответы без сжатия, сохраняя сжатие для веб-интерфейса, JSON и статических ресурсов.

При развёртывании с CDN сначала закройте origin межсетевым экраном так, чтобы к нему могли подключаться только актуальные исходящие CIDR CDN. Затем настройте именно эти диапазоны как доверенные прокси Caddy и формируйте вышестоящие заголовки из разобранного Caddy значения `{client_ip}`. Например:

```caddyfile
{
	servers {
		trusted_proxies static 192.0.2.0/24 2001:db8:1234::/48
		trusted_proxies_strict
		client_ip_headers CF-Connecting-IP X-Forwarded-For
	}
}

api.example.com {
	reverse_proxy 127.0.0.1:8080 {
		header_up X-Real-IP {client_ip}
		header_up X-Forwarded-For {client_ip}
	}
}
```

Замените документационные диапазоны опубликованными и автоматически поддерживаемыми актуальными исходящими диапазонами CDN. `CF-Connecting-IP` здесь безопасен только потому, что прямой доступ к origin закрыт, а Caddy доверяет лишь указанным непосредственным TCP-узлам. Настройте `server.trusted_proxies` Sub2API на адрес Caddy или его частную подсеть, чтобы приложение принимало только заголовки, переписанные Caddy.

В ядре Caddy нет универсального ограничителя частоты запросов; используйте доверенный CDN/WAF, поддерживаемый модуль ограничения частоты либо правила межсетевого экрана хоста.

На CDN/WAF настройте ограничения соединений, заголовков и тел, проверки для ботов и лимиты по IP/ASN до поступления трафика на origin. Разрешайте входящий доступ к origin только с исходящих CIDR CDN либо из частного балансировщика. Не открывайте порт приложения в публичный Интернет.

## Граница защиты от DDoS

Проверки приложения уменьшают усиление нагрузки после установления соединения с Go. Они не способны поглотить объёмные атаки, потоки TLS-соединений, насыщение канала или большую распределённую совокупность источников. Для этого необходимы пропускная способность вышестоящей сети, фильтрация CDN/WAF, правила межсетевого экрана провайдера и изоляция origin. Во время шквала отклоняемых запросов избегайте метрик с высокой кардинальностью и записи отдельного события безопасности в базу данных для каждого запроса.
