# MCP для управления платформой (OAuth)

[中文](mcp.md) | Русский

Платформа включает удалённый MCP-сервис с подключением через **Streamable HTTP + код авторизации OAuth / S256 PKCE**. Клиенту достаточно указать адрес MCP; при подключении в браузере открывается вход в платформу, после чего пользователь явно соглашается на личную или административную область доступа и права только на чтение либо на чтение и запись. Создавать, копировать или хранить статический токен не нужно.

## Развёртывание

MCP по умолчанию выключен. Ресурсный интерфейс MCP, обнаружение OAuth и регистрация клиентов становятся доступны, а в боковой панели появляется **Подключение MCP**, только после явной настройки стабильного, доверенного публичного адреса MCP. Например:

```sh
MCP_PUBLIC_URL=https://api.example.com/api/v1/mcp
```

Адрес также можно задать в файле конфигурации:

```yaml
mcp:
  public_url: https://api.example.com/api/v1/mcp
```

Адрес должен указывать на `/api/v1/mcp` непосредственно в корне сайта, без завершающего слеша, параметров запроса или фрагмента. Точки обнаружения OAuth также находятся в корне сайта, поэтому развёртывание под подпутём, например `https://example.com/sub2api/`, не поддерживается. В рабочей среде используйте HTTPS; при локальной разработке допускается HTTP с localhost или loopback IP. Сервис не выводит этот адрес из URL фронтенда, Host запроса или пересылаемых заголовков. Если адрес не задан, MCP и его интерфейсы OAuth возвращают 503. Очистка этой настройки отключает MCP, после чего уже выданные токены невозможно использовать.

При развёртывании на одном домене достаточно указанного адреса MCP. Если фронтенд и бэкенд размещены на разных доменах, дополнительно задайте URL фронтенда платформы в административных настройках или `SERVER_FRONTEND_URL`, чтобы найти браузерную страницу авторизации. Обратный прокси должен передавать `/api/v1/mcp`, `/api/v1/mcp/oauth/*` и перечисленные ниже точки обнаружения `/.well-known/*`, сохраняя заголовки Authorization, Accept и заголовки протокола MCP. Доступ браузерного клиента к ресурсу MCP также должен соответствовать белому списку CORS/Origin платформы.

## Подключение

1. Добавьте `https://api.example.com/api/v1/mcp` в клиенте, поддерживающем удалённый MCP OAuth.
2. Клиент обнаружит сервер авторизации, зарегистрирует публичный клиент и автоматически создаст параметры PKCE.
3. В браузере откроется страница входа и предоставления доступа. Проверьте имя приложения и адрес возврата, выберите область доступа и права, затем подтвердите согласие.
4. Клиент автоматически обменяет код авторизации и будет обновлять токен доступа.

Для клиентов, использующих в конфигурации `mcpServers` и `url`:

```json
{
  "mcpServers": {
    "sub2api": {
      "url": "https://api.example.com/api/v1/mcp"
    }
  }
}
```

У разных клиентов структура конфигурации может отличаться; транспорт — Streamable HTTP, аутентификация — OAuth. Платформа не принимает в качестве учётных данных MCP API Key для вызова моделей, браузерный JWT, административный API Key или статический MCP-токен.

## Предоставление и отзыв доступа

По умолчанию предоставляется **личная область доступа только для чтения**. Администратор может явно выбрать административную область при подтверждении согласия; если включена дополнительная проверка чувствительных операций платформы, предоставление административной области также требует step-up. Для предоставления **административной области с правами чтения и записи** TOTP должен быть включён и одна проверка step-up должна быть пройдена независимо от состояния этой настройки.

- **Личная область**: операции только с данными текущего пользователя; даже если согласие даёт администратор, административные инструменты не открываются.
- **Административная область**: доступна для предоставления только администратору; разрешает административные инструменты из каталога и собственные личные инструменты.
- **Только чтение**: инструменты записи не отображаются в списке; прямой вызов инструмента записи также отклоняется.
- **Чтение и запись**: открываются инструменты изменения в соответствующей области, включая удаление API Key, корректировку баланса, отключение аккаунта и отзыв подписки.

OAuth scope имеет значение `mcp`; фактические права на инструменты определяются областью и режимом чтения/записи, подтверждёнными в браузере. Обновление токена не расширяет права: для изменения прав необходима новая авторизация. Имя приложения поступает из запроса регистрации и не означает, что платформа проверила это приложение; страница согласия также показывает его адрес обратного вызова.

Код авторизации действует 5 минут и может быть обменён только один раз. Токен доступа действует не более 10 минут; авторизация и refresh-токен действуют не более 30 дней, причём refresh-токен ротируется при каждом использовании. Повторное использование кода авторизации или уже использованного refresh-токена приводит к отзыву соответствующей авторизации. Сервер хранит только дайджесты учётных данных.

После входа в платформу в разделе боковой панели **Подключение MCP** (`/settings/mcp`) можно просматривать авторизованные приложения и отзывать их доступ. У одного пользователя может быть не более 20 действующих авторизаций. Отзыв, смена пароля или идентификатора входа и отключение пользователя блокируют последующие вызовы и обновление токенов; после потери роли администратора его административные авторизации также недействительны. Действие «Отозвать все сеансы» отзывает и все MCP-авторизации пользователя. При отключении пользователя все его авторизации отзываются постоянно, а при снятии роли администратора постоянно отзываются его административные авторизации: последующее включение пользователя или возврат роли не восстанавливает старый доступ. Страница не показывает токены доступа или обновления; MCP-инструменты не могут самостоятельно предоставить новую авторизацию.

## Каталог инструментов

Через `tools/list` клиент получает инструменты, доступные текущей OAuth-авторизации, и полные описания их параметров.

| Область | Инструменты | Назначение |
| --- | --- | --- |
| Личная | `user_get_profile`, `user_get_platform_quotas` | Просмотр профиля, баланса, лимитов и квот платформ |
| Личная | `user_list_groups`, `user_list_channels` | Просмотр доступных групп, каналов и моделей |
| Личная | `user_list_api_keys`, `user_get_api_key` | Запрос метаданных и лимитов собственных API Key |
| Личная | `user_create_api_key`, `user_update_api_key`, `user_delete_api_key` | Создание, изменение, отключение или удаление собственных API Key |
| Личная | `user_list_usage`, `user_get_usage_stats`, `user_get_dashboard` | Запрос подробностей запросов, статистики использования и дашборда |
| Личная | `user_list_subscriptions`, `user_get_subscription_summary` | Просмотр собственных подписок и оставшихся квот |
| Административная | `admin_get_dashboard`, `admin_get_ops_overview` | Статистика работы платформы и обзор эксплуатации |
| Административная | `admin_list_users`, `admin_get_user`, `admin_update_user`, `admin_update_user_balance` | Запрос пользователей, изменение статуса, лимитов, прав групп и баланса |
| Административная | `admin_list_groups`, `admin_get_group`, `admin_create_group`, `admin_update_group`, `admin_delete_group` | Управление основными настройками групп, ценовыми коэффициентами, квотами и списками разрешённых моделей |
| Административная | `admin_list_accounts`, `admin_get_account`, `admin_update_account`, `admin_set_account_schedulable`, `admin_clear_account_error` | Управление состоянием, планированием, параллелизмом, приоритетом и сроком действия вышестоящих аккаунтов |
| Административная | `admin_list_usage`, `admin_get_usage_stats` | Запрос подробностей запросов и статистики использования по всей платформе |
| Административная | `admin_list_subscriptions`, `admin_get_subscription`, `admin_assign_subscription`, `admin_extend_subscription`, `admin_revoke_subscription` | Запрос, назначение, продление и отзыв подписок |

Инструменты открывают только явно перечисленные поля. Нет инструмента для произвольного HTTP-запроса или URL, изменения пароля или роли, привязки идентификаторов, управления учётными данными вышестоящих сервисов, резервного копирования и восстановления либо платежей. Из обычных результатов чтения и изменения удаляются учётные данные, включая API Key и вышестоящие токены. Результат `user_create_api_key` содержит новый API Key для настройки приложения; не публикуйте этот результат.

Продолжают действовать существующие бизнес-разрешения, проверки принадлежности ресурсов, ограничения режима платформы, подтверждения административного соответствия требованиям, лимиты запросов и аудит операций. Рекомендации, возвращённые моделью, не обходят эти правила. Каждый вызов инструмента MCP, включая запросы только на чтение, записывается в аудит операций с методом аутентификации `mcp_oauth` и полями `mcp_grant_id` и `mcp_tool`.

## Примеры параметров

Параметры инструментов используют поля `id`, `query` и `body`. ID ресурса из пути указывается в `id` верхнего уровня, условия поиска — в `query`, изменяемые поля — в `body`. Поля, не указанные при обновлении, сохраняют прежнее значение; неизвестные поля отклоняются. Нумерация страниц начинается с 1, размер страницы не превышает 100 записей.

Создание API Key, корректировка баланса пользователя и продление подписки дополнительно требуют `idempotency_key` верхнего уровня; можно использовать UUID. При повторе той же операции сохраняйте прежние значение ключа и параметры, а для новой операции используйте новый ключ. Платформа использует существующий механизм идемпотентности, чтобы повтор после тайм-аута не создал объект или списание/зачисление дважды.

Запрос собственного использования:

```json
{
  "name": "user_list_usage",
  "arguments": {
    "query": {
      "page": 1,
      "page_size": 20,
      "start_date": "2026-10-01",
      "end_date": "2026-10-28",
      "timezone": "Asia/Shanghai"
    }
  }
}
```

Формат даты — `YYYY-MM-DD`; начальная и конечная даты включаются в интервал статистики, часовой пояс задаётся именем IANA. Для произвольного интервала административной статистики указывайте обе даты.

Создание личного API Key с квотой и сроком действия:

```json
{
  "name": "user_create_api_key",
  "arguments": {
    "idempotency_key": "create-development-key-20261028-1",
    "body": {
      "name": "development",
      "group_id": 12,
      "quota": 10,
      "expires_in_days": 7
    }
  }
}
```

Сначала используйте `user_list_groups`, чтобы подтвердить доступный ID группы. Для этой операции требуется авторизация с правом чтения и записи в личной или административной области.

Приостановка планирования вышестоящего аккаунта:

```json
{
  "name": "admin_set_account_schedulable",
  "arguments": {
    "id": 42,
    "body": { "schedulable": false }
  }
}
```

Корректировка баланса и назначение подписки изменяют реальные права на оплачиваемое использование. Перед отправкой проверьте получателя и сумму либо число дней; после тайм-аута клиента сначала запросите результат, а не повторяйте вызов вслепую.

## Протокол и обнаружение

| Точка доступа | Назначение |
| --- | --- |
| `GET /.well-known/oauth-protected-resource/api/v1/mcp` | Метаданные ресурса по RFC 9728; обнаружение также доступно по корневому `/.well-known/oauth-protected-resource` |
| `GET /.well-known/oauth-authorization-server` | Метаданные сервера авторизации по RFC 8414 |
| `POST /api/v1/mcp/oauth/register` | Динамическая регистрация публичного клиента по RFC 7591; возвращает HTTP 201 |
| `/oauth/mcp/authorize` | Страница входа во фронтенд и явного согласия |
| `POST /api/v1/mcp/oauth/token` | Обмен кода авторизации и обновление токена; данные формы |
| `POST /api/v1/mcp/oauth/revoke` | Отзыв по RFC 7009; данные формы |

Неаутентифицированный запрос MCP получает 401; заголовок `WWW-Authenticate` содержит `resource_metadata` и `scope="mcp"`. Клиенты поддерживаются только с `token_endpoint_auth_method=none`, `response_type=code`, S256 PKCE и grant type кода авторизации или обновления токена. URI обратного вызова должен в точности совпадать с зарегистрированным и использовать HTTPS либо локальный HTTP; шаблоны не поддерживаются. Автоматическая загрузка удалённого client metadata URL сейчас не предоставляется. Тело запроса регистрации не превышает 4 KiB; `client_name` содержит не более 100 символов и не может включать управляющие, двунаправленные управляющие, нулевой ширины и другие невидимые символы.

Запрос авторизации и обмен кода должны содержать `resource`, точно совпадающий с адресом MCP. При обновлении `resource` можно опустить — тогда используется исходная авторизация; другой ресурс отклоняется. `state` возвращается клиенту без изменения. Код авторизации привязан к клиенту, обратному вызову, ресурсу и PKCE; клиент должен надёжно хранить verifier и refresh-токен.

Просмотр сведений для обнаружения:

```sh
curl 'https://api.example.com/.well-known/oauth-protected-resource/api/v1/mcp'
curl 'https://api.example.com/.well-known/oauth-authorization-server'
```

Сервис использует режим Streamable HTTP без состояния из официального Go MCP SDK; POST возвращает JSON, а поток событий GET и операции сеанса DELETE возвращают 405. Каждый HTTP-запрос может содержать только один объект JSON-RPC; пакетные запросы JSON-RPC, в том числе запросы старой версии без `MCP-Protocol-Version`, всегда получают 400. Авторизация заново проверяется при каждом HTTP-запросе, кэширование ответов запрещено. Результат инструмента возвращается как JSON в одном текстовом блоке `{"http_status": …, "result": …}` и больше не дублируется в `structuredContent`; результат размером более 2 MiB после кодирования отклоняется — сузьте интервал запроса или размер страницы. Ошибка бизнес-API возвращается результатом инструмента с `isError: true`, а исходный HTTP-статус находится в `http_status`. Время выполнения инструмента ограничено 30 секундами; отмена при отключении клиента передаётся дальше. После тайм-аута операции записи проверьте состояние, прежде чем решать, повторять ли вызов.

Для `/api/v1/mcp` сначала действует лимит по IP клиента до аутентификации (600 запросов в минуту), затем отдельный входной лимит по пользователю после аутентификации. Каждый фактический вызов инструмента расходует только одну единицу глобального лимита административной части; агрегированная статистика по-прежнему ограничивается лимитом Heavy. Время последнего использования авторизации записывается не чаще одного раза в минуту. Для динамической регистрации, обмена токенов и отзыва действуют отдельные лимиты по IP. Эти лимиты считают всю подсеть IPv6 /64 одним клиентом и отклоняют запросы при недоступности Redis.

## Разработка

Каталог инструментов находится в `backend/internal/managementmcp/catalog.go`. Новый инструмент следует привязывать к существующему административному маршруту, задавать закрытую schema параметров и покрывать тестами права доступа, принадлежность ресурсов, границы параметров и удаление учётных данных.

Хранилище OAuth создаётся миграцией `249_mcp_oauth.sql`. Динамическая регистрация не записывает данные в базу: `client_id` — подписанный сервером идентификатор без состояния, содержащий имя клиента, дайджест URI обратного вызова и grant type. Ключ подписи создаётся при первом использовании, сохраняется в `security_secrets` и используется совместно несколькими экземплярами. Запись авторизации создаётся только после согласия пользователя, поэтому анонимная регистрация не занимает хранилище и не имеет общего лимита, который можно исчерпать. При каждой новой авторизации выполняется ограниченная по объёму очистка авторизаций, истёкших более 7 дней назад. Браузер использует защищённый JWT интерфейс `/api/v1/user/mcp/config` для получения настроенного сервером адреса подключения, `/api/v1/user/mcp/authorize` для предварительного просмотра и решения о предоставлении доступа, а также `/api/v1/user/mcp/grants` для списка и отзыва. Протокольные точки клиента возвращают стандартный OAuth JSON; браузерные интерфейсы используют существующий формат ответов платформы.
