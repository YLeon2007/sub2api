# HTTP-статус нативных изображений Codex и тайм-ауты прокси

[English](OPENAI_IMAGES_CODEX.md) | Русский

Непотоковые запросы `/v1/images/generations` и `/v1/images/edits` с заголовком `X-Codex-Image-Turn-Id` ожидают итоговый ответ без промежуточных пробельных сигналов поддержания соединения. Это сохраняет фактический HTTP-статус ошибки. Иначе ранний сигнал уже фиксирует HTTP 200, и Codex может принять позднюю ошибку за неполный ответ изображения (например, без поля `created`).

Для остальных клиентов сохраняется поведение, заданное `gateway.image_nonstream_keepalive_interval`. Потоковые ответы Images не меняются. Заголовок сообщает о возможности клиента; он не аутентифицирует запрос и не даёт разрешения на генерацию изображений.

## Бюджет времени ожидания

Прокси перед Sub2API должен допускать всю операцию с изображением, включая очередь, выбор аккаунта и обработку у провайдера, до первого байта ответа. Предельное время ожидания заголовков ответа от вышестоящего сервиса и тайм-аут чтения при простое должны превышать этот бюджет. Одного увеличения общего тайм-аута HTTP-клиента недостаточно, если у прокси остаётся короткий предел. Согласуйте настройки клиента, всех промежуточных прокси и вышестоящего HTTP-транспорта; выберите конечное время ожидания под своё развёртывание. Например, при бюджете изображений 900 секунд в nginx требуется `proxy_read_timeout 900s` либо большее значение с запасом на планирование. Проверьте внешний CDN/балансировщик: изменение nginx не меняет его ограничение.

Отключение сигналов поддержания соединения не ускоряет генерацию. Тайм-аут прокси может сработать, пока провайдер продолжает генерировать и начислять плату. Перед повторной попыткой выясните состояние исходного запроса: тайм-аут не доказывает, что генерация не запускалась. Исправление обработки статуса не устраняет ошибки квоты или разрешений провайдера.

## Регрессионные проверки

Тесты обработчика регистрируют оба настоящих маршрута, разбирают JSON-запрос генерации и multipart-запрос редактирования, выбирают аккаунт и отправляют HTTP-запрос локальному вышестоящему сервису с задержкой. Локальный обратный прокси с достаточным сроком ожидания заголовков получает итоговый HTTP 400 или успешный JSON изображения после обычного интервала сигнала поддержания соединения. Прокси с более коротким сроком ожидания прерывает нативные запросы, но продолжает получать сигналы для обычных клиентов. Это контролируемые тестовые сценарии, а не подтверждение успешной платной генерации или проверка конкретного развёрнутого CDN.
